# House Tracker

A fun house management app for tracking dishes washed, fridge inventory, and more house tasks.

## Stack

- Next.js (App Router, TypeScript, Tailwind)
- Supabase (Postgres + client SDK)

## Setup

1. Create a Supabase project at https://supabase.com.
2. In the SQL editor, run `supabase/migrations/0001_init.sql` to create the tables
   (`roommates`, `dish_tally`, `fridge_items`) and seed 6 placeholder roommates.
   Then run `supabase/migrations/0002_dish_calendar.sql`. It renames the six
   placeholders while preserving their IDs, adds daily dish completions, and
   carries existing dish history into the calendar (one completion per day).
3. Copy `env.example` to `.env.local` and fill in your project's URL and anon key
   (Supabase dashboard → Project Settings → API).
4. Install dependencies and run the dev server:

   ```bash
   npm install
   npm run dev
   ```

5. Open http://localhost:3000.

6. Set up the approved house accounts using [supabase/AUTH_SETUP.md](supabase/AUTH_SETUP.md).
   Apply migration `0003_house_auth.sql`, create the approved Auth users, link
   each user to their roommate. The app
   requires a house member login for the home page, dishes, and fridge.

7. Run `supabase/migrations/0004_dish_reviews.sql` in the SQL editor. It creates
   the private `dish-photos` Storage bucket and adds the inbox, submissions, voting functions, and
   house-member access policies. No extra Storage dashboard setup is needed.

## Features (MVP)

- **Dish Duty** (`/dishes`) — a Monday–Sunday calendar with week navigation.
  Alex, Anson, Brandon, Jiayi, Kevin, and Vincent cover Monday–Saturday;
  Sunday is shared. Submit a photo for today or a past day as the
  signed-in member, including when covering a shift. The other five members
  receive an in-app inbox notification and can each vote once. Three approvals
  complete the day; three rejections allow a fresh submission. Pending days are
  amber, approved days are green, unfinished current/past days are red, and
  future days are grey. Photos are temporarily hosted in private Supabase
  Storage for the review, then deleted once voting closes.
  The calendar uses Toronto time and prevents duplicate or future check-ins.
  An all-time leaderboard gives the person who washed 3 points for an approved submission on
  that calendar date, 1 for a late submission, and 0 for incomplete days. Ties share
  a rank. Six generated character portraits are in `public/avatars/`, with their
  prompts documented there.
- **House inbox** (`/inbox`) — private per-member notifications, review photos,
  approval/rejection voting, vote history, and a sent-submissions view. Unread
  counts appear in navigation on every authenticated page. Active pages refresh
  every 15 seconds; no SMTP or browser notification permissions are needed.
- **Fridge Management** (`/fridge`) — add items with quantity/expiry, see what's
  expiring soon, mark items as finished.

## Notes

- Email/password login authenticates approved house members. Server-side checks and
  Row Level Security enforce membership. Members submit dish/fridge entries as
  themselves, and check-in timestamps are generated by the database.
- Dish photos accept JPG, PNG, WebP, AVIF, and GIF up to 20 MB. Only approved
  house members can read them. The database keeps paths and review/vote records,
  never image bytes. Reviews need three other members to vote, so provision at
  least three accounts in addition to the submitter for a decision.
- Voting and notification creation are atomic database functions; clients cannot
  forge voters, self-vote, vote twice, set submission timestamps, or insert an
  approved completion directly. Points use the original submission timestamp.
- The server deletes the photo through the Storage API after a decision, then
  confirms that removal before displaying “deleted.” If removal fails, active
  house sessions retry it every minute. There is no background scheduler while
  everyone is offline; pending reviews retain their photo until a decision.
  No service-role key is needed. Failed submissions attempt to remove unused
  uploads; ambiguous network failures can leave a private draft for admin cleanup.
- `npm test` runs calendar/auth/upload tests plus the real migrations and RLS/
  voting checks in an isolated PostgreSQL WASM runtime (PGlite), with local
  Auth and Storage metadata fixtures. It never touches the live database.
- Accounts are created and linked by the house administrator. Normal password
  login does not need custom SMTP; recovery emails would need it for members
  outside the Supabase project team.
- More house tasks (chores, bills, etc.) can be added as new tables + pages
  following the same pattern.
